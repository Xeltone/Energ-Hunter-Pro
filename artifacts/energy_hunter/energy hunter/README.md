# ⚡ Energy Hunter Pro

Energy Hunter Pro - это продвинутое веб-приложение для учета энергетических напитков. Отслеживайте то, что вы пробовали, добавляйте в коллекцию новые вкусы и соревнуйтесь с другими охотниками за энергией!

## 🚀 Последние обновления (Версия 2.0)

### 1. ☁️ Бэкенд и Синхронизация (Node.js + SQLite)
- Добавлен полноценный сервер для безопасного хранения данных.
- Внедрена система авторизации (Регистрация/Вход с использованием JWT-токенов).
- Реализована синхронизация локальной базы данных с сервером (кнопки **"В облако"** и **"Из облака"**).

### 2. 🏆 Глобальный Лидерборд
- Вкладка **"Рейтинг"**: теперь можно посмотреть топ-50 пользователей по количеству засинхронизированных банок.
- Занимайте первые места и получайте медали 🥇, 🥈, 🥉 в реальном времени!

### 3. 👤 Расширенный Профиль и Ранги
- Добавлен стильный градиентный баннер пользователя с уникальным аватаром.
- **Динамические звания** в зависимости от размера коллекции (от *Охотник-Новичок* до *Мастер Энергии*).
- Автоматический подсчет всей облачной статистики: **Количество банок**, **Суммарный кофеин (мг)** и **Суммарный сахар (г)**.
- Отображение даты регистрации в гильдии.

### 4. 📱 Современный Интерфейс (UX/UI)
- Главное меню переработано в стильную **выдвигающуюся боковую панель (Sidebar)** с эффектом прозрачного стекла (`backdrop-filter`).
- Плавное затемнение заднего фона при открытии меню для комфортной навигации.
- Идеальная адаптация интерфейса для мобильных устройств (переработаны отступы и позиционирование заголовков).
- Исправление критических багов (включая фикс бесконечного разлогина из-за конфликта DOM-элементов).

## 🛠 Технологии
- **Frontend**: HTML5, Vanilla CSS (Glassmorphism дизайн), Vanilla JavaScript, Chart.js (локально), html2canvas (локально).
- **Backend**: Node.js, Express, SQLite3, JSON Web Tokens (JWT), bcrypt.

## 🔒 Безопасность и деплой
- В **продакшене** обязательно: `HTTPS`, `JWT_SECRET`, `ALLOWED_ORIGINS=https://ваш-домен`.
- Rate-limit на auth/sync — in-memory (сбрасывается при рестарте; для нескольких инстансов нужен Redis).
- База `*.db` и `.jwt_secret` не должны попадать в репозиторий / публичные архивы.
- Имя пользователя: 3–32 символа, буквы (латиница/кириллица), цифры, `_` `-` `.`

## 🐛 Исправления (v2.1)
Полный список — в [CHANGELOG.md](./CHANGELOG.md).

- Синхронизация чанками через **staging**: облачная копия меняется только после успешной загрузки всех частей.
- Сахар «не указан» больше не превращается в `0` после облака (`NULL` в БД).
- Одинаковое сообщение при ошибке входа (без enumeration логинов).
- `saveData()` пишет глубокую копию, а не ссылку на массив.
- Таймауты fetch показывают понятное сообщение.
- Chart.js и html2canvas подключены локально и кэшируются service worker (офлайн-графики).
